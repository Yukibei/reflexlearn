## 二、需要正视的三个问题

### 2.1 token 流式一帧都没出，用户要干等 238 秒 —— 已修复

**根因**：PERF-A 的流式只接在 `generate_resource`（中心化 fan-out）上，而 planner 常把
`collab_mode` 判成 `pipeline`，真实会话走的是 `pipeline_node` —— 那里一处流式接线都没有。
「接线三层都对却不工作」，是因为对的是另一条路。

排查按层隔离，每层留证据：网关层探针实测 `complete_stream` 产出 48 个增量（正常）；
LangGraph 层最小复现 `Send` fan-out + `get_stream_writer`（custom 帧正常）；接线层
`SkillContext.delta_sink` / `doc_gen` / `generate_text` 三处都对；最后靠日志里
**只有 `pipeline_diag`、没有 `generator_diag`** 定位到走错分支。

**修复**：抽出 `nodes/stream_bridge.py` 供两种协作模式共用，`pipeline_node` 接入增量推送。

体检当时的原始记录（单次真实会话）：

```
first_signal=0.23s   TTFC(first resource_card)=238.25s   total(done)=265.41s
frames={'session':1,'agent_step':7,'resource_card':12,'learning_path':1,'space_saved':1,'done':1}
resource_card 分布: 首=238.25s 末=238.27s 共12帧
```

修复后同一探针：

```
TTFD(first resource_delta)=31.42s   delta_frames=836
TTFC=261.14s   total=281.96s
```

总时长基本不变（由 6 个资源的生成耗时决定），但用户从「干等 4 分钟毫无反馈」变成
「31 秒开始逐字看到内容」。**总时长仍是待解决的性能问题，见 §4。**

### 2.2 学习路径这次是规则排序，不是 LLM 个性化

```
09:11:54 INFO path_plan degraded (llm ValidationError) -> rule based
```

LLM 返回的路径结构没通过 schema 校验，于是回落到规则排序。降级本身是对的（不崩），
但用户看到的「个性化学习路径」这一次实际是规则产物。ValidationError 是偶发还是稳定复现，
需要多跑几次确认；如果稳定，说明 prompt 与 schema 不匹配，属于真缺陷而非环境问题。

### 2.3 RAG 有基础设施但没有知识

`knowledge_chunks` 只有 15 个点（约 1–2 篇文档），`experience_memory` 6 个点。
检索链路本身是通的（Qdrant 在、reranker 已预热 2.3s），但没有知识可检索，
所以「混合 RAG」当前对回答质量的实际贡献接近于零。这不是代码缺陷，是**数据缺口**——
要么灌真实知识库，要么在演示时诚实说明。
