# 启动与发布说明

本文档用于接手开发、评审演示和 GitHub 发布前检查。所有运行、调试、测试操作必须通过 `scripts/` 目录下的脚本完成。

## 一、环境准备

### 1. 基础工具

- Python 使用 `.venv` 虚拟环境。
- Python 依赖管理使用 `uv`。
- 前端依赖由 `frontend/package-lock.json` 锁定。
- 本地服务日志统一输出到 `logs/`。

### 2. 环境变量

首次启动前复制配置：

```bash
cp .env.example .env
```

开发演示可使用 `.env.example` 中的默认演示账号；生产环境必须修改以下值：

```text
APP_ENV
AUTH_SECRET_KEY
AUTH_DEMO_PASSWORD
CORS_ALLOW_ORIGINS
TRUSTED_HOSTS
DATABASE_URL
REDIS_URL
QDRANT_URL
```

生产环境下后端会拒绝默认密钥、默认演示密码以及关闭鉴权的配置。

## 二、本地启动

### 1. 启动核心依赖

```bash
bash scripts/start_core.sh
```

核心依赖主要覆盖 PostgreSQL、Redis、Qdrant 等基础服务。

### 2. 初始化数据

```bash
bash scripts/init_all.sh
```

该脚本负责数据库、向量库和内置知识样例初始化。

### 3. 启动 API

```bash
bash scripts/start_api.sh
```

API 地址：

```text
http://127.0.0.1:28000
```

健康检查：

```text
http://127.0.0.1:28000/api/health
```

### 4. 启动前端

```bash
bash scripts/start_frontend.sh
```

前端地址：

```text
http://127.0.0.1:23002
```

端口取自 `.env` 的 `API_PORT` / `FRONTEND_PORT`，位置参数可临时覆盖。
前端 API base 保持相对 `/api`（Next rewrites 同源代理），不要传绝对地址，否则会丢会话 cookie。

默认演示登录：

```text
用户名：admin
密码：reflexlearn-admin
```

### 5. 停止服务

```bash
bash scripts/stop_frontend.sh
bash scripts/stop_api.sh
bash scripts/stop_all.sh
```

## 三、验证命令

### 1. 单元测试

```bash
bash scripts/test_unit.sh
```

### 2. 前端构建

```bash
bash scripts/build_frontend.sh
```

### 3. API 安全冒烟

```bash
bash scripts/check_api_security.sh 8000
```

检查范围包括：

- health 接口可用；
- auth login 可用；
- 受保护路由没有 Bearer token 时会被拒绝；
- 上传 guard 的基础校验；
- 视频任务提交的鉴权边界。

### 4. API 集成真写

```bash
bash scripts/check_api_integrations.sh 8000
```

该脚本依赖 Qdrant/PostgreSQL 等中间件可用，用于验证知识上传真写和视频降级链路。

### 5. Shell 脚本语法检查

```bash
bash -n scripts/*.sh
```

## 四、生产环境事实

- 公网入口：`https://learn.liyilin.xyz/`
- 服务器项目目录：`/data/apps/reflexlearn`
- Compose 文件：`deploy/compose.production.yml`
- API 内网检查：`http://127.0.0.1:18000/api/health`
- Web 内网检查：`http://127.0.0.1:13000/`
- 环境配置只保存在服务器 `.env`，任何发布归档均不得携带它。
- 当前没有 CI/CD；`git push` 不会自动部署生产环境。

判断发布成功必须同时满足：`postgres/redis/qdrant/api/web` 容器运行、API 内网健康、Web 内网
可访问、公网 HTTPS 可访问。统一由 `scripts/check_production.sh` 检查，不以端口监听代替服务归属验证。

## 五、发布前门禁

1. 工作区只包含本次预期改动，且敏感文件未进入 Git。
2. 通过与改动范围相称的 `scripts/test_unit.sh` 测试。
3. 发布前提交代码，版本建议使用 `YYYYMMDD-<短提交号>`。
4. 前端发布前先执行 `bash scripts/stop_frontend.sh`，避免 dev 与 build 共写 `.next`。
5. 增量发布要求服务器已有对应的 `api` 或 `web` 容器；首次部署使用第七节的全栈流程。

## 六、增量发布

发布机必须能通过 SSH 登录生产服务器。使用独立私钥时，将其 Bash 路径写入临时环境变量；
例如 Windows `E:\yuki.pem` 在 Git Bash 中通常对应 `/e/yuki.pem`。私钥路径不写入 `.env` 或仓库。
以下命令中的 `DEPLOY_TARGET` 要替换为真实的 `用户@主机`。

### 1. API

```bash
DEPLOY_TARGET='user@example.com'
REFLEXLEARN_SSH_IDENTITY=/e/yuki.pem \
  bash scripts/release_api_production.sh 20260811-<短提交号> "$DEPLOY_TARGET"
```

单入口依次执行：生成最小 API 源码归档、排除 `.env`/密钥、计算 SHA-256、上传归档与安装器、
远端校验路径和摘要、备份当前源码、构建并切换 API、运行生产健康检查。失败时
`deploy_api_production.sh` 恢复旧镜像，安装器恢复旧源码。数据库结构变更不会自动执行 `init`；
有 schema 变更时需单独评审并显式运行初始化服务。

### 2. 前端

```bash
DEPLOY_TARGET='user@example.com'
REFLEXLEARN_SSH_IDENTITY=/e/yuki.pem \
  bash scripts/release_frontend_production.sh 20260811-<短提交号> "$DEPLOY_TARGET"
```

单入口依次执行既有前端构建脚本，生成源码与 standalone 运行时双归档，校验 SHA-256 后上传；
服务器构建版本镜像、备份当前前端源码、切换 Web 并运行生产健康检查。失败时恢复旧镜像和源码。

每次成功发布后，服务器分别写入：

```text
runtime/current-api-release
runtime/current-frontend-release
```

完整归档保存在 `runtime/releases/`，发布前源码备份保存在 `/data/backups/reflexlearn/`。

## 七、首次全栈部署

首次部署要先在服务器创建 `/data/apps/reflexlearn/.env` 并配置生产密钥、域名和数据库凭证，
然后在服务器项目目录执行：

```bash
bash scripts/deploy_production.sh
bash scripts/check_production.sh
```

首次全栈脚本会构建并启动 PostgreSQL、Redis、Qdrant、初始化服务、API 与 Web。后续日常发布一律使用
第六节的单服务入口，保留独立回滚边界。
